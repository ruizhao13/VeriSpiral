# 有限故障诊断与验证器比较

`make diagnosis-demo` 运行一个小型公开机制实验：在故障解释与检查成本已声明时，
逐次执行可负担的检查，保留并发失败指示，并给出下一步工作建议。它不调用模型，也不生成新算法、
构造新验证器或决定接受规格修订。

实现：[有限适配器](../src/verispiral/diagnosis_demo.py)、
[控制器](../src/verispiral/diagnosis.py)。证据：
[参考报告](../examples/expected/diagnosis/diagnosis_report.json)、
[控制器测试](../tests/test_diagnosis.py)、
[适配器与参考输出测试](../tests/test_diagnosis_golden.py)。
下述数值仅描述这些有限表与确定性计算。

## 一个可逐项核查的例子

每个候选在四个情境中的损失由公开表直接给定；越小越好。目标是四项平均损失。
这些候选是损失向量，不是智能体发现或运行的算法。

| 候选 | 四个情境损失 | 廉价检查：前两项均值 | 完整检查：四项均值 |
| --- | --- | --- | --- |
| stable | 2, 2, 2, 2 | 2 | 2 |
| tail_failure | 0, 0, 0, 12 | 0 | 3 |
| weak | 8, 8, 8, 8 | 8 | 8 |

廉价检查选择 `tail_failure`，相对这个候选池的完整目标后悔为 `3 - 2 = 1`。
以平均损失不超过 2 为通过条件，它产生一次误晋级；两个检查都没有误拒。
完整枚举选择 `stable`，池内后悔为 0。这说明在这张构造表上，必须检查实际选中的
候选，不能只看廉价分数是否改善。

完整枚举与参考评价是同一个有限均值，因此其零误差由构造决定，不是独立校准证据。
两行比较不是等预算效果实验，也不证明枚举在真实问题上更好。

## 建造成本与调用成本

报告为两个已写好的机制分别声明建造成本 1 和 6；每次调用检查一个候选，调用成本
分别为 2 和 4。假设复用 100 次，摊销为 `1/100 + 2 = 201/100` 与
`6/100 + 4 = 203/50`。100 是规划假设，不是执行了 100 次实验。
这些单位是人工设定的成本模型，不是测得的时间、token 或实验费用。
实际研究必须加入校准、独立锚评、失败重试、维护和修订后重检成本，见
[等预算评价协议](research-agenda.md)。

## 七类检查、一个对照与两个并发例子

适配器修改有限表、报告值或重复测量偏移，然后真正计算各项检查。
下表是完整观测下的设计预期；标签只在诊断结束后用于核对，不传给选择器。
类别名仅指建议的后续工作方向，输出使用明确的失败指示名，不把检查失败当作原因认定。

| 后续工作方向 | 检查失败指示 | 检查内容 |
| --- | --- | --- |
| Algorithm | `algorithm_dominated` | 候选同时被廉价、完整、参考评价中的比较方法严格支配 |
| Verifier | `verifier_disagreement` | 廉价与完整评价不相等 |
| Setup | `setup_mean_disagreement` | 建模内与参考情境的均值不相等 |
| Goal | `goal_rank_disagreement` | 均值与最大损失对候选和比较方法的偏好不一致 |
| Implementation | `implementation_disagreement` | 报告值不等于重新计算值 |
| Noise | `replicate_disagreement` | 预设重复测量结果不一致 |
| Gaming | `fresh_mean_disagreement` | 开发情境与另一公开情境的均值不一致 |
| 对照 | 空列表 | 所有上述检查通过，仅报告这些检查的有限结果 |

两个并发例子分别同时触发“报告值不一致 + 重复结果不一致”和“廉价评价不一致 +
另一情境均值不一致”。它们由实际表值和偏移计算出两项失败，选择器不读取植入标签，
不从单故障签名推算叠加关系。十个例子均在完整预算下执行七项检查，再输出全部已观察
失败指示。先遇到某一项失败不会让其余项自动通过。

完整检查成本分别由报告中的 `test_cost_units` 声明，总额为 18。每例默认预算为 18，
另有预算为 1 的未决例子。重新计算报告值没有独立实现的证据地位；固定偏移不是
真实随机采样，精确相等也不是适合一般噪声问题的统计检验。

## 控制器到底计算什么

默认演示使用 `choose_factor_diagnostic_action`。输入是“失败指示 → 独立可观察的检查”
的一对一映射、检查成本、已观察结果和剩余预算。这里的独立仅表示每个指示由自身检查
直接读取，不假设统计独立，也不假设原因可以简单叠加。检查返回 `False` 才加入
`supported_factors`；尚未观察的指示保留在 `unresolved_factors`。通过的检查只排除
本次该检查的失败指示，不能排除整个故障类别。

选择器按低成本、再按检查名选择未观察且可负担的检查，每执行一次才读取结果并扣费。
所有注册检查完成才返回 `diagnosis_supported` 与 `coverage_checked: true`，否则预算
不足就返回 `budget_exhausted` 并列出 `pending_tests`。多个失败可同时保留，未决状态
也保留已观察到的失败；动作始终是建议，不自动修订规格或接受科学主张。
这里不声称实现了最优检查分配：全部检查都要做，顺序只是确定性的低成本优先。

例如 `case_09` 同时含报告偏移和重复结果偏移。预算 2 时已支持
`implementation_disagreement`，但 `replicate_disagreement` 仍未决；预算 18 时两项
均被观察并返回。完整预算相较原来的首次唯一签名停止需要更多检查费用，报告显式计入
这部分覆盖成本，不宣称诊断提速。

控制器仍保留 `choose_diagnostic_action`，供调用者提供完整联合签名的有限模型使用。
它先排除与观测冲突的签名；若剩下 n 个签名，检查把它们分成大小为
`n_true`、`n_false` 的两组，其分数为：

```text
[n - (n_true² + n_false²) / n] / cost
```

这是相等权重下每单位成本的预期排除数，用有理数精确比较；不是熵、校准概率或学习
策略。可负担检查中取最高分，同分优先低成本、再按检查名排序。即使只剩一个签名，
仍要执行剩余零分检查以检验一致性，不能把未执行的预测当成证据。

联合签名模式只有在全部注册检查观察完毕且恰有一个一致签名时，才返回
`diagnosis_supported`；完全覆盖后仍有相同签名则为 `inconclusive`；任意已观察结果
排除所有签名时立即返回 `model_mismatch`。没有可负担的待检项则为
`budget_exhausted`。报告保留旧的单故障签名作为比较材料：面对 `case_09`，该旧模型
现在会继续检查并报告不匹配，不会只输出 Implementation；它不会凭空生成并发签名。

## 不能从这次演示推出什么

- 每项失败指示对应一个预先声明的窄检查，成功列出这些指示不检验现实因果诊断准确率。
- 两个并发例子证明当前适配器能保留这些实际观察到的同时失败，不证明能发现任意
  未知故障或交互。检查之间有交互时需要明确联合模型，不能自动叠加单故障解释。
- 完整覆盖仅指注册检查已经执行，不能保证所需检查本身完整。
- 只比较均值会漏掉保持均值的情境变化；测试也保留了这种不可见变化。
- 所有表、预测与所谓另一情境都公开可见，不是隐藏测试或独立最终评估。
- 此诊断适配器始终有有限表参考；它本身不检验缺少可信锚点时如何构造锚点。
- Goal、Setup、Verifier 的生成、真实候选搜索、领域迁移、独立校准和真实成本比较
  仍需按[研究议程](research-agenda.md)另做实验。

测试确认有限机制及其限制，golden 检查确认逐字节复现。
真正检验课题需要冻结外部目标锚点、对齐总预算、引入独立任务和基线，并保留未知、
误拒与失败任务；不能把这些开发夹具重新命名为最终测试集。
