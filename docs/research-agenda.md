# 研究议程：在预算内共同设计问题、检查器与算法

本文是待检验的研究计划，不报告实验效果、科学发现或新颖性结论。
现有证据范围见[主张与证据矩阵](claim-evidence-matrix.md)。

## 核心问题

在有限时间、计算、昂贵评估和人工判断预算下，如何共同改进
**Goal/Metric、Setup、Verifier 与 Algorithm**，使被选中的候选在目标情境中更有价值？
系统需要判断下一步应改算法、补一个区分性实验、修正检查器，还是重新讨论问题。
用户对目标及规格的决定权是必要约束；版本控制本身不是全部研究贡献。

| 对象 | 设计问题 | 需要保留的证据 |
| --- | --- | --- |
| Goal/Metric | 希望改善什么，如何观察价值，哪些代价不可接受？ | 目标定义、外部锚点、指标遗漏与取舍 |
| Setup | 哪些环境、假设和任务足以代表目标情境？ | 纳入与排除范围、反例、迁移检查 |
| Verifier | 哪些低成本检查足以决定继续、拒绝或升级评估？ | 检查成本、漏检、误拒、适用范围 |
| Algorithm | 在既定条件下采取什么方法？ | 候选内容、依赖、执行结果与失败记录 |

这里有两次可能失真的压缩：现实需求被压缩为 Setup 和 Goal/Metric；
昂贵目标评估被压缩为廉价 Verifier。第一层失真需要目标情境或外部锚点来检查；
第二层失真需要昂贵评估来检查。检查器内部自洽不能验证这两层映射。

## 可证伪的主假设

**H1（待检验）：**在预注册任务、相同候选机会和相同预算下，按竞争性故障解释
选择区分性实验，再决定修改对象，比只优化算法或无诊断地轮流修改对象，
能降低最终 top-k 候选的迁移后悔，同时不超过预注册的误晋级、误拒和人工成本容限。

检验单位是一次完整任务运行；候选、轮次或重复查看同一结果不算独立任务。
开发阶段确定最小有用改进量、非劣容限、重复次数和不确定性报告方法，随后冻结。
若最终评估没有达到这些预设条件，就不支持 H1；不能只报告其中改善的指标。
当前确定性回放不能检验 H1，也不能估计真实科研任务上的效果。

次要问题包括：建造更好的检查器需要复用多少次才值得；廉价分数在全体候选上
相关时，其最高分集合是否仍能迁移；反复优化是否使候选利用检查器盲点。
这些都需要单独的预注册分析，不由一次成功晋级推断。

## 下一步动作与故障诊断

每次失败先保留竞争解释：算法不足、检查器失真、Setup 不适用、目标指标偏离需求、
实现错误，以及随机波动或对检查器的投机。多个原因可以并存；没有区分证据时保留未知。

诊断包包含观察、竞争解释、可区分它们的实验、结果分支、成本、停止条件和建议修改对象。
实验按预期区分能力及成本选择，但只有校准过的概率才能用于概率性效用计算。
当前有限适配器以可分别观察的检查失败指示保留并发异常，不将它们当作独占原因。
完成状态要求执行全部注册检查，预算不足时保留已观察失败和未决项。旧的签名接口
仍使用等权下预期排除数的选择启发式，并要求剩余检查验证一致性；它不是校准故障概率。
十个公开例子只验证这些机制；未知、交互或检查不可见的故障仍可能遗漏。

多保真评估按廉价筛查、针对性反例、中等成本验证、昂贵目标锚点评估逐级晋级。
晋级是继续投入预算的决定，不能自动成为科学主张；保留一部分预算检查被拒候选，
否则无法发现筛查带来的误拒。所有晋级规则、保留预算和终止条件须在最终测试前冻结。

## 统一预算的对照与消融

| 组别 | 可变部分 | 用途 |
| --- | --- | --- |
| 算法搜索基线 | 固定 Goal/Metric、Setup、Verifier，仅改 Algorithm | 检验共同设计是否值得额外成本 |
| 昂贵评估基线 | 固定 Goal/Metric、Setup，按预算直接使用目标锚点 | 检验廉价检查器是否带来净收益 |
| 无诊断共同设计 | 可提出同类修改，按预注册轮换规则分配实验 | 区分共同设计与诊断选实验的作用 |
| 完整方案 | 竞争解释、预算内区分实验、多保真晋级 | 检验 H1 |
| 消融 | 分别去掉诊断、反例检查、或多保真晋级 | 定位收益与代价来源；不合并消融解释 |

各组使用相同任务、候选生成器或候选池、可用工具、初始信息与用户授权边界。
先在固定候选池比较决策机制，再单独研究候选生成；不得把更强生成器当作机制收益。
目标变更产生独立问题分支，不能把新目标上的成功计作原目标得分。
冻结原始目标锚点用于最终横向比较；对共同设计产生的新目标另做明确标注的探索评价。

预算同时限制总计算/时间、昂贵锚点调用、模型调用和人工审阅；不可只对齐轮数。
构建、校准、失败实验、重试、修订后重检及最终评估的成本都记录。
资源单位不兼容时报告成本向量，不任意相加成一个分数。
单一资源单位内，可报告复用 n 次的摊销成本：
`每次成本 = 构建成本 / n + 平均调用与维护成本`。
n、复用任务分布、维护范围和失效后重建成本须明示；测试反馈不能算作免费构建材料。

## 指标及分母

预先固定候选池、k、锚点、有效候选阈值和目标效用 G（越大越好）。
各组必须为提交的全部候选完成规定锚点评估；预算不足以填满 k 个时报告未完成，
不能通过少提交降低误晋级率。最终评价所用独立锚点预算对各组一致并单独列账。

| 指标 | 操作定义 | 防止误读 |
| --- | --- | --- |
| top-k 误晋级率 | top-k 中未达到预设锚点条件的数量 / k | 没有锚点结果不能当作通过 |
| 误拒率 | 决策阶段拒绝的合格候选数 / 共同候选池中合格候选数 | 小池全量锚评；大池用预注册抽样估计并报告不确定性 |
| top-k 迁移后悔 | 共同池按目标情境 G 选出的最佳 k 个平均效用，减去提交集合平均效用 | 参照只限共同池；不是全局最优性结论 |
| 晋级迁移差 | 同一提交集合在开发 Setup 与目标情境的锚点效用差 | 度量必须可比较，不能跨指标直接相减 |
| 成本 | 构建、调用、维护、锚点、人工审阅次数与耗时 | 同时报总成本和摊销成本 |
| 未完成与未知 | 未填满 k、无锚点、预算耗尽、无法区分的任务比例 | 纳入主报告，不能删除失败任务 |

全体候选上的相关性或排序一致性仅作为次要诊断；主要比较必须检查实际被选的 top-k。
报告跨任务分布、逐任务结果和不确定性，保留不同故障类型的失败记录。
如 G 是多目标且未获得权重授权，报告预注册约束与 Pareto 比较，不擅自生成总分。

## 开发、反例与最终测试的污染政策

1. **开发集：**允许观察结果、改检查器和选超参数；记录全部适应过程与成本。
2. **反例集：**用于攻击盲点、实现错误和投机；一旦据此修改，它就是开发材料。
3. **最终测试集：**在方法、阈值、预算、任务排除规则和主分析冻结后只运行预定评价。
   由独立保管者或隔离流程控制反馈；具体机制尚待实现，不能声称当前公开仓库已实现隔离。
4. 查看最终结果后修改方案，应停止把该集合称为未见测试，并安排新的独立评价。
   保留原结果；禁止以“修复检查器”为由覆盖失败记录。

仓库内所有候选、故障签名和参考输出均可公开检查，因此只能用于机制演示或开发验证。
它们不是隐藏测试，也不能证明对新任务或未知故障的泛化。
实际研究的受控测试材料不应因此复制进本公开仓库；公开结果需使用另行许可的材料。

## 缺少目标锚点时如何推进

先区分“尚未测量”与“目标尚未定义”。前者优先做小规模校准、外部复核或区分实验；
后者先形成可由用户判断的目标选项及取舍，暂停按单一分数搜索。
来源一致、模型自评或用户偏好可以帮助定义目标，但不能替代经验效度或数学证明。
若连受限范围内的锚点也不可获得，仅交付假设、决策包和待验证方案；
不报告真实目标改进、误晋级率或迁移后悔的数值。

## 分阶段里程碑与停止判据

| 阶段 | 可交付成果 | 停止或缩小范围的条件 |
| --- | --- | --- |
| M0：机制原型 | 小型公开故障实例、有限适配器、预算与未知状态、可重复参考输出 | 依赖透露真实故障标签才能选实验，或靠放宽门禁才通过 |
| M1：有限受控比较 | 冻结候选池、独立锚点、上述基线与完整成本账 | 没有可用锚点、结果不可区分，或加入建造成本后没有预设有用改进 |
| M2：加入候选搜索 | 同生成器、相同预算、多任务重复，检查 top-k 和投机 | 只改善代理分数、误拒/人工成本超容限，或收益完全来自生成器差异 |
| M3：限定领域迁移 | 新任务上的冻结方案评价、失败边界与复用成本 | 收益仅来自接触测试反馈，或新情境的锚点不再可比 |

## 从问题表现返回协议修订

采用[问题驱动迭代协议](../prompts/protocols/problem_driven_iteration.md)，每轮先冻结问题契约、
外部目标、对照、成本向量和可区分竞争解释的观察，再运行一个可审阅的小问题。
讨论中的核心想法只作为假设来源；是否修改项目，要由问题表现和可执行检查支持。
修订保留失败及未知，重跑旧案例和预先指定的新案例；用于修订的反馈均记为开发材料。
每轮修复并复核一个具体缺陷后停止；若没有预定收益或预算耗尽，也停止并保留结果。
下一轮需要不同案例或尚未解决的边界，不能将反复改写协议当作泛化证据。

已执行的[最短路证书试验](path-workflow-study.md)比较可行性检查、路径边检查与
完整证书，并使用分别编写的路径评分、穷举参考和直接动态规划对照。
它暴露并修复了弱检查的误接受以及最优路径的证书缺失，但补证书包含完整求解工作，
没有建立相对直接方法的效率收益。这个公开开发案例支持具体协议修复，不检验 H1。
