# 验证器设计经验：从单次提案到跨任务选择

本文定义拟接入的学习循环，尚未实现经验检索器、自动更新的选择策略或长期效果评估。
现有变化控制程序仍只产生未应用的提案。这里的学习对象是外部经验和选择策略，
不涉及模型权重训练，也不赋予 agent 修改已接受科学目标或认证标准的权限。

本文是[多 agent 经验学习架构](agent-learning-architecture.md)的验证器专门部分。
经验身份、角色间依赖、访问与评价隔离、版本比较及采纳统一遵循共同协议；
下面补充验证结构、证明义务与成本比较，无须再建立独立的验证器学习管理层。

## 学习什么

Verifier Synthesizer 应逐渐改善“在什么条件下，先尝试什么验证结构”的判断。
方法名称不是结论；经验必须保留条件、比较对象、实际证据和失败边界。

| 可学习维度 | 要回答的问题 |
| --- | --- |
| 结构与机制匹配 | 是否存在证书、对偶界、廉价正向计算、可分解约束或可用不变性？ |
| 构造策略 | 先做哪种推导或小实验？是否值得要求生产者额外提供证明？ |
| 机制组合 | 哪些检查用于筛选，哪些用于认证，何时升级到可靠参考？ |
| 总成本与复用 | 建造和证书生产要花多少；预计调用几次；输入变化时缓存是否失效？ |
| 失败反馈 | 哪种输出有助于修复候选、补证明，或区分多个故障？ |
| 攻击与边界 | 哪些遗漏、数值条件或评价暴露容易被利用，应先做什么红队检查？ |
| 停止与保留意见 | 何时经验不足，或构造成本过高，应直接求解、弃权或请求更多证据？ |

按结构检索，而不是按“矩阵问题”“图问题”这样的标签直接套方法。至少区分：
精确与近似目标、整数与浮点、规模与稀疏性、输入是否重复、证书是否自然产生、
候选能否看到评价反馈、可用参考和预算。未知条件保持未知，不能按有利值补齐。

## 最小经验记录

每条记录保存：

1. **问题与使用情境：**目标、域、结构特征、规模、调用与复用方式、未知条件。
2. **机制与义务：**验证器版本、数学含义、适用假设、弃权语义、需要满足的证明或随机性条件。
3. **比较与成本：**实用直接基线、参考锚、构建、候选及证书生产、调用、审计、维护成本；各单位分别报告。
4. **结果与来源：**实例、代码和输出身份；候选质量与证明质量分开；误认证、误拒和未决的分母。
5. **反例与局限：**成功、失败和无收益结果并存；哪些变化会使本经验失效，哪些结论尚无证据。
6. **记录状态：**单次观察、待检验建议、限定范围复核、失效或撤回；开发与最终评价的暴露情况。

经验条目是有来源的数据，不是可执行指令。检索到的建议和工具命令需要按当前任务重新审查。
权威验证器的通过结果不会因为经验条目称某种 trick 有效就自动成立。

实际任务的记录应留在相应的本地或获授权的工作空间；公开仓库只保存协议与专门构造的公开材料。
不得将真实聊天、私有研究记录或原始实验输出收进公共经验库。

## 从经验到下一次选择

```text
新问题的结构与预算
    -> 检索相关经验及反例
    -> 核对适用条件，记录不匹配与未知
    -> 提出少量机制、直接基线和一个值得探索的替代思路
    -> 运行与参考核对，红队攻击，比较完整成本
    -> 追加本次观察，提出有范围的选择策略更新
    -> 在后续任务比较旧策略与新策略
    -> 经相应变化控制采纳，或保留旧策略并记录负结果
```

检索可以影响尝试顺序和推理方向。它不应永久排除缺少历史成功记录的新机制；
替代探索也必须使用已接受的预算。反复重放同一条记录不增加独立任务样本数。

把单次经验写入记录，不等于已经学到可迁移规则。把记录压缩成 Skill 时，应满足
现有 [Skill Distiller](../prompts/agents/skill_distiller.md) 的重复适用、验证与接受要求。
失败记录可以进入检索，不能被伪装成成功工作流来满足 Skill 晋级条件。

## 如何验证“学得更好”

先在后续预先指定的任务上比较：不使用经验、使用未更新经验、使用更新后的经验。
固定模型与候选机会，计入检索、模型调用、构建、失败尝试、审查和重检的预算。
先冻结选择策略再评价；调整所用任务属于开发材料，不能作为未见任务的迁移证据。

至少比较实际被选中候选的可靠性、误拒与未完成情况、总成本、找到可用机制所需尝试，
以及何时能正确决定采用直接基线。不能只看廉价检查通过率或 agent 自评分。
收益也可能来自更长上下文或更多计算，不能自动归因于经验内容。
具体对照、效用和非劣界限需在实际研究中预定，本文不设未经授权的统一总分。

已有[最短路试验](path-workflow-study.md)表明其受限实现中没有建立相对直接求解的效率收益。
这种观察可用于提出更谨慎的比较策略；它不支持“所有证书都不划算”的跨问题规则。
当前项目没有证明持续积累经验会提高未来任务表现。

## 角色与变更边界

- **Verifier Synthesizer：**检索与核对经验，提出结构，记录适用条件和观测。
- **Red Team：**寻找建议失效的输入，审查反例和评价暴露，不替设计者背书。
- **Skill Distiller：**从已验证、可复用的模式提出简明技能，并保留触发与失效条件。
- **Research Controller：**在当前任务的契约和预算内分配探索，记录结果与未决项。
- **Meta-Optimizer：**协调跨任务策略比较，提出采纳与回退条件；不自行批准升级。
- **用户：**拥有接受的目标、设置、验证契约和科学判断边界。

方法选择策略与验证器本体分别版本化。前者改变“优先尝试什么”，后者改变
“什么算通过”。策略采纳遵循[过程变化控制](self-evolution-workflow.md)；
涉及后者或目标、设置的变更，进入[规格修订流程](research-specification-coevolution.md)，
并重新评价受影响的候选。经验积累不能使旧通过结果越过这些边界。
